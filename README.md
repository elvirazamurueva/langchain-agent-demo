# langchain-agent-demo

Небольшой учебный проект на Python, который показывает три возможности LangChain:

1. **AI-агент** принимает сообщение пользователя и отвечает.
2. Агент **помнит контекст** разговора между сообщениями (memory / checkpointer).
3. Агент **самостоятельно вызывает пользовательский tool** (`get_cat_fact`).

Модель подключается не к OpenAI напрямую, а к **GenAPI** — сервису с
OpenAI-совместимым API.

---

## Простыми словами: что тут происходит

- **LangChain** — это библиотека-«конструктор» для приложений с LLM. Она
  даёт готовые «кирпичики»: подключение к модели, инструменты, память,
  агентов, — чтобы не писать всё с нуля.
- **Агент** — это не просто «вопрос → ответ». Агент умеет *решать*, что
  делать: ответить самому, вызвать инструмент, вызвать ещё один
  инструмент и только потом сформулировать ответ. Внутри это цикл
  «подумал → вызвал инструмент → посмотрел результат → ответил».
- **Tool (инструмент)** — обычная Python-функция, которую агент может
  вызвать по своему усмотрению. Здесь это `get_cat_fact`: он возвращает
  факт о породе кошки из локального словаря. Никакого интернета — только
  чтобы показать сам механизм.
- **Memory / checkpointer** — механизм, который сохраняет состояние
  разговора (все сообщения) между вызовами агента. В этом проекте
  используется `InMemorySaver` из LangGraph: он хранит историю в
  оперативной памяти, пока работает программа.
- **`thread_id`** — «номер разговора». История привязана к нему: два
  сообщения с одним и тем же `thread_id` — это один диалог, а с разными —
  два независимых диалога, которые друг о друге не знают.

### Чем это отличается от обычного вызова LLM

Обычный вызов модели — это один запрос, после которого модель «забывает»
всё. Чтобы она «помнила» контекст, нужно каждый раз вручную пересылать
всю историю сообщений. Агент же:

- сам накапливает историю (checkpointer);
- сам решает, когда вызвать инструмент;
- сам встраивает результат инструмента в ответ.

## Установка и запуск

### 1. Открыть папку проекта в терминале

```bash
cd langchain-agent-demo
```

### 2. Создать виртуальное окружение и установить зависимости

Windows (PowerShell / CMD):

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Windows (Git Bash):

```bash
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
```

### 3. Указать API-ключ

Откройте `.env` и впишите свой ключ GenAPI:

```
GENAPI_API_KEY=ваш_ключ
GENAPI_URL=https://proxy.gen-api.ru/v1/chat/completions
MODEL_ID=gpt-4o-mini
```

> В `.env` можно указывать **полный** URL с `/chat/completions` — проект
> сам превратит его в `base_url` вида `.../v1`, который ожидает
> библиотека `ChatOpenAI` (OpenAI SDK сам добавляет `/chat/completions`).
> Менять `.env` вручную под требования библиотеки не нужно.

### 4. Запустить

```bash
python main.py
```

## Команды в консоли

| Команда | Действие |
|---|---|
| любой текст | отправить сообщение агенту |
| `new` | начать новый разговор (новый `thread_id`) |
| `exit` | завершить программу |

## Как проверить работу памяти

Запустите `python main.py` и введите подряд:

```
Вы: Меня зовут Елена.
Агент: Приятно познакомиться, Елена! Чем могу помочь?

Вы: Как меня зовут?
Агент: Вас зовут Елена.
```

Агент помнит имя, потому что оба сообщения относятся к одному
`thread_id`.

Теперь введите `new` — начнётся новый разговор с новым `thread_id`:

```
Вы: new
Начат новый разговор. thread_id: <новый-id>

Вы: Как меня зовут?
Агент: Я не знаю вашего имени — вы ещё не называли его.
```

Новый `thread_id` — это отдельная история, старый контекст в нём недоступен.

---

## Как проверить работу tool

В том же диалоге спросите про породу кошки:

```
Вы: Расскажи интересный факт о мейн-куне.
Агент: Мейн-кун — одна из самых крупных домашних пород: взрослый кот
       может весить 7–12 кг, а длина тела вместе с хвостом иногда
       превышает 1 метр.
```

Агент сам поймёт, что для ответа нужен инструмент `get_cat_fact`,
вызовет его и использует результат. Доступные породы: **мейн-кун**,
**британская короткошёрстная**, **сиамская**, **сфинкс**.

Проверить инструмент отдельно, без модели:

```bash
python -c "from tools import get_cat_fact; print(get_cat_fact.invoke({'breed': 'сфинкс'}))"
```

## Автоматические проверки

```bash
python test_demo.py
```

Скрипт проверяет:

- проект импортируется без ошибок;
- конфигурация правильно преобразует `GENAPI_URL` в `base_url`;
- инструмент `get_cat_fact` возвращает факты и корректно отвечает на
  неизвестную породу;
- память (checkpointer) сохраняет состояние в рамках одного `thread_id`
  и изолирует разные `thread_id`.

Проверка памяти выполняется на встроенной тестовой модели, поэтому
API-ключ для неё не нужен. Если в `.env` задан `GENAPI_API_KEY`,
дополнительно выполняется живая проверка подключения к GenAPI.

## Безопасность

- Значение `GENAPI_API_KEY` **никогда** не выводится в консоль и не
  пишется в логи.
- Файл `.env` добавлен в `.gitignore` и не попадёт в Git.
- В репозитории есть только `.env.example` с заглушкой вместо ключа.
